## 固定协议

仅使用 CUDA，没有 CPU 训练降级路径。主实验采用全划分、200 轮、种子 41–50；具体运行参数以 configs 中的文件为准。Cora/CiteSeer 使用公共节点划分，MNIST/CIFAR10 使用各自官方完整训练/验证/测试划分。

两个节点任务沿用两层、16 维 GIN，仅第二层有聚合提示；两个图任务使用四层、110 维 GIN，保留输入 GPF-plus，每个聚合提示层 rank 2，20 个提示。CIFAR10 输入为三通道特征加二维位置，使用 README 的 GIN-CIFAR10 量化学习率与 norm 步长初始化；Cora 使用 README 的 GIN-Cora 存储惩罚。

改进版沿用此前零左因子、条件标准化/截断、RMS 查询及幅度缩放、均匀分层 rank；随机基和误差谱基单列。本轮没有悄悄修正上一轮发现的条件分布变化问题，因此这是对既定方法的完整验证。离线训练校准和误差谱计算可在 CPU 完成，所有训练更新必须在 GPU。

同数据集、同种子共享初始骨干和数据顺序。GPU scatter 的归约可能存在微小数值不确定性，配对种子不等于 GPU 运算逐位可复现。每轮保存模型、优化器、调度器、随机数和数据顺序状态；中断后从已提交轮次继续。按最低验证 CE 选模，平局取早。每个数据集全部预定训练完成后，每个最佳检查点只测试一次；不按测试结果筛选变体。

校准只用训练节点/图，最多 4096 节点/层，图任务最多用前 128 张训练图。局部误差诊断只在验证数据上计算，固定当前层输入，仅绕过当前层消息量化；不是完整 FP32 模型差异。提示开销和实际有效位宽单独记录，存储惩罚目标不保证预算达成。

## 运行与恢复

所有工作进程从此次 source_snapshot 执行，后续工作区修改不影响这批训练。progress.json 记录实时轮次，last.pt 支持续训，best.pt 保存验证最优权重。对同一结果目录重复恢复不会重复已完成训练或已有测试结果。

暂停：在结果根目录创建 STOP 文件，运行中的训练完成当前轮次后暂停。恢复和查看状态的命令见 RUN_COMMANDS.md。测试开始后若进程异常退出且结果未保存，会停止该项，不会自动重复测试。

结果包含配置、数据划分索引、代码与环境快照、校准、逐轮日志、检查点、局部误差、实际位宽和逐种子 CSV。没有完成全部实验前，不据阶段性结果宣称方法优越。

## 收尾复核修复

160 组均已完成 200 轮 CUDA 训练。收尾时，CIFAR10/spectral_basis/50 的最佳模型验证复核及 MNIST/main/49 的测试前验证复核未通过，随后原汇总审计也因同一数值阈值停止。恢复前最终测试完成 119 组。

对两个异常检查点及审计异常的 CIFAR10/spectral_basis/44，仅在 GPU 验证集重复评估各 5 次：同一 CIFAR10 模型损失相对原日志最多偏移约 0.000210，且模型状态不变；MNIST 原异常未在这 5 次复核中重现。原复核绝对阈值为 0.0001。此行为与 CUDA 聚合及量化边界的数值不确定性相符，未据此修改模型方法。

恢复使用预先固定的验证 CE 绝对容差 0.0005，并增加严格的逐张量一致性检查：best.pt 必须与 last.pt 中保存的最佳模型完全相同，且轮次、损失必须精确对应原日志中最早的验证损失最小值。训练轮数、超参数、选模规则及测试前向均不变；已有 119 个测试结果直接复用，尚未开始的测试仍只运行一次。

原始 source_snapshot、provenance.json 及失败日志保留；恢复前状态归档在 recovery_before/，修复后的执行代码另存 recovery_snapshot_v1/，变更和哈希见 recovery.patch、recovery_provenance.json。数值复核原始记录见 recovery_probe.json。修复通过 9 项测试，含真实 CUDA 训练、断点恢复与防止重复测试；恢复前已通过 159 个结果的检查点及选模审计。
