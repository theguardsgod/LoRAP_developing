# GPF-LoRAP 验证集调参：剩余六个组合

范围为 DQ–Cora–GIN、QAT–CIFAR10–GCN、DQ–ZINC–GCN、DQ–CiteSeer–GAT、
DQ–MNIST–GAT、A2Q–ZINC–GAT。用户授权对这些落后组合调整参数；历史结果保留。
目标是提高性能。每轮内部只根据验证任务损失选择候选和检查点。
后续轮次的目标组合和是否继续调参由此前测试比较触发，因此整个过程属于
反复查看同一测试集后的探索性调参，报告为 tuned GPF-LoRAP 对 fixed GraphLoRA；
不能将其描述为完全独立于测试结果的一次性最终评估。

每个组合固定八个候选，准确配置在 `space.py`，运行时全部写入 `study.json`。
提示数取 10/20，rank 取 2/4/8，提示学习率为原骨干主学习率的 0.1/0.3/1/3 倍，
输入和聚合提示的固定残差尺度取 0.1/1，采用原 Xavier 或零残差初始化。
零残差只清零输入提示及低秩左因子，右因子保留随机初始化。
两个候选调整骨干学习率；A2Q 同时尝试较小的量化器学习率。
架构、宽度、量化位宽边界、存储预算、存储损失系数和数据划分保持原值。
所有参数仍按原联合训练冻结规则训练。提示权重衰减固定为零。

固定的分阶段预算如下：

1. 种子 41 跑每个组合的八个候选。图任务用完整训练集训练 30 轮，完整验证集选模；
   两个便宜的节点任务直接训练完整 200/250 轮，避免过早剪枝。
2. 每个组合按最低验证损失保留两个候选。图任务从第 30 轮完整恢复优化器、调度器和
   随机数状态，续训至原定 200 轮，不重新开始，也不改变调度器时间轴。
3. 每个组合在这两个候选中按完整训练的最低验证损失选定一个配置，锁定之后再补齐
   种子 42、43。种子 41 的完整训练直接复用，最终始终报告三个种子。
4. 六个配置全部锁定、18 个选定模型全部训练完成后，各最佳检查点只测试一次。
   其他候选不读取测试集，不使用测试分数挑选种子或在新旧配置中取较高值。

无数值失败时，共有 48 次候选筛选、其中 12 个候选入围，再新增 12 次种子复验；
60 个不同训练实例，并非 144 个潜在配置全部训练。完整训练的种子 41 不重复计算。
图任务的 30 轮筛选是速度与筛选可靠性的取舍，发生在第 50 轮学习率衰减之前。
若搜索阶段出现非有限损失/梯度，该候选留存失败记录并排除；最终三个种子不得缺失。

运行入口（使用 ProG Python）：

```sh
python -B -m runs.lorap_study.table1_gpf_search.run prepare --root OUTPUT
```

worker 必须从 `OUTPUT/source_snapshot` 目录启动，以运行被归档的代码：

```sh
python -B -m runs.lorap_study.table1_gpf_search.run worker --root /absolute/OUTPUT --device cuda:0
```

GPU worker 用文件锁领取任务、推进阶段和释放最终测试。每轮保存断点；
根目录 `STOP` 文件使进程在 epoch 边界暂停，移除后重启 worker 即可恢复。
`--smoke` 独立运行每个候选的一轮筛选与两轮完整训练，图任务仅用训练/验证各八张图，
绝不访问测试集。正式训练使用完整官方划分。

`REPORT.md`、`status.json`、`validation_trials.csv`、`resources.csv`、
`paired_differences.csv` 和 `table1_tuned_rows.tex` 随流水线自动更新。
全部候选、晋级和最终选择均有记录，确认阶段的验证成绩不会改变已经锁定的配置。
